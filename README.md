# DREAMDUO — النسخة الأولية

## الملفات
- `index.html`: بنية صفحات اللعبة.
- `style.css`: التصميم المتجاوب والألوان.
- `script.js`: اختيار المظهر والصفات، إنشاء رابط تجريبي، وحساب نسبة التشابه.
- `schema.sql`: مخطط قاعدة بيانات أولي مقترح للمرحلة التالية.

## التشغيل
افتحي `index.html` في متصفح حديث. الأفضل استخدام VS Code مع Live Server عندما يتوفر الحاسوب. لا توجد مكتبات JavaScript مطلوبة للتشغيل المحلي.

## ما الذي يعمل في هذه النسخة؟
- إنشاء شخصية أصلية.
- اختيار نوع الشخصية والشعر والبشرة والعينين والملابس والإكسسوارات.
- تقييم ست صفات من 1 إلى 5.
- إنشاء رابط تجريبي يحمل بيانات الشخصية في الجزء `#challenge=...`.
- فتح الرابط في متصفح آخر لتجربة تصميم الصديق.
- حساب نسبة تشابه ترفيهية وعرض ملاحظة.
- نسخ الرابط أو النتيجة.

## حدود النسخة
- لا توجد قاعدة بيانات متصلة.
- لا يتم إرسال تصاميم الأصدقاء إلى صاحب الرابط ولا حفظها على خادم.
- البيانات المضمنة في الرابط ليست سرية؛ لا تضعي معلومات شخصية فيها.
- الرابط لن يعمل على أجهزة أخرى إلا بعد رفع ملفات الموقع إلى استضافة عامة.
- يمكن لمن لديه الرابط تعديل الجزء الموجود بعد `#challenge=`، لذلك لا يُستخدم هذا الأسلوب للتحقق من الهوية أو حفظ نتائج موثوقة.

## المرحلة التالية للنشر
1. نشر الملفات الثابتة في خدمة استضافة مثل GitHub Pages.
2. إنشاء قاعدة بيانات على Supabase.
3. إضافة معرّف عشوائي لكل تحدٍ بدل وضع بيانات الشخصية كاملة داخل الرابط.
4. إعداد سياسات Row Level Security والتحقق من صلاحيات القراءة والكتابة.
5. بناء طريقة آمنة لعرض النتائج لصاحب التحدي والصديق الذي أرسل تصميمه.

لا تضعي مفاتيح الخدمة السرية في `script.js`. في الواجهة العامة يستخدم مفتاح Supabase القابل للنشر فقط مع سياسات أمان صحيحة؛ مفاتيح الخدمة السرية تبقى في الخادم.
